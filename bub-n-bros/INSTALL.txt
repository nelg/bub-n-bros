Requirements (Python 3)
-----------------------

This version runs on Python 3 (tested with Python 3.14).  The old
Python 2 code is no longer supported, but the network protocol has not
changed: Python 3 servers and clients can still play with Python 2 ones
and with the Java applet.

  * Server and web launcher: only the Python standard library.

  * Client, one of these display drivers:
      - pygame       ("pip install pygame" or your distribution's package,
                      e.g. python-pygame); also provides sound and music
      - gtk          GTK 3 through PyGObject and pycairo
      - X            the 'xshm' C extension; build it with "make"
                     (needs the X11, Xext and Xrender development headers)

  * Or, instead of the Python client: the native client (see below).

Quick start:

    python3 BubBob.py              # web launcher on http://127.0.0.1:8000/
    python3 bubbob/bb.py bubbob/levels/Levels.bin   # server only
    python3 display/Client.py host:port        # client only

The native client (Linux, Windows, macOS)
----------------------------------------

rust-client/ contains a second client written in Rust.  It is a single
executable with no dependencies on Python or on the game files: the
graphics, sounds, music and levels are downloaded from the server (and
cached), so it can join any Bub-n-Bros server, old or new.  It supports
full screen, sound and music, several players per keyboard, and finding
servers on the local network.

  * Ready-made binaries for Linux, Windows and macOS are built by GitHub
    (see docs/building-native-client.md, "Ready-made binaries").

  * To compile it yourself, install Rust (https://rustup.rs) and, on
    Linux, the ALSA, X11, Xi and OpenGL development packages, then:

        cd rust-client
        cargo build --release

    The program is rust-client/target/release/bubnbros-client
    (bubnbros-client.exe on Windows).  docs/building-native-client.md has
    step-by-step instructions for each platform, including
    cross-compiling for Windows from Linux and universal macOS binaries.

  * The Arch Linux package (packing/arch/) includes it as
    /usr/bin/bubbros-native, with its own menu entry.

  * Playing alone: just start bubnbros-client without arguments.  If no
    server runs on this computer, it starts one for you ("Play alone
    mode"); the release binaries have the server built in, so this needs
    no Python.

  * Playing: start a server (python3 BubBob.py, or bubbob/bb.py), then

        bubnbros-client                  # find a server on this machine / LAN
        bubnbros-client host:port        # or connect to a given server
        bubnbros-client --fullscreen --name=Me host:port

    Click on a dragon at the bottom of the window and press the four keys
    you want for right, left, jump and fire.  F11 switches full screen,
    F7 / F8 change the volume, F9 mutes, Esc quits.  See
    rust-client/README.md for all the options.

Known limitations of the Python 3 version:

  * the clock bonus is disabled: it relied on the 'statesaver'
    extension, which copies running generators and cannot be built for
    Python 3 (the game already ran without it when it was not compiled);
  * the 'linux' sound driver needs the old linuxaudiodev and audioop
    modules, which are gone from Python 3; use the pygame sound driver;
  * the native Windows driver (display/windows/wingame.c) has not been
    ported; use pygame on Windows.


Installation on *NIX
--------------------

NOTE!! THIS IS STILL EXPERIMENTAL. The game does not have to be
       installed to play. The currently directory layout was not
       designed with Unix-style installation in mind. For a
       QUICK START see in doc/Introduction.html.

The game (and the man pages) can be installed on *NIX systems into a
standard location like this:

1) Check locations and permissions in the top-level Makefile. The game
   is installed into /usr/local by default.

2) Optionally run "make" to build the xshm extension used by the X
   display driver.

3) Run "make install" as root or other user with sufficient rights.

NOTE!! The game logic is still quite directory-layout dependant ATM so
       installing is implemented by copying the whole directory into
       /usr/local/lib/ (the location can be changed in the Makefile)
       and making symlinks to appropriate directories. This procedure
       will probably be cleaned up in future releases.

Downloads and distribution packages
-----------------------------------

The game comes in three forms, which do the same thing (install one):

  native           the game on the system's Python (needs Python 3 and
                   pygame), with all the clients: the Python client and
                   the native client (bubbros-native) without a built-in
                   server, which plays alone with the Python server
  server-embedded  the game server as one program with its own Python
                   inside (PyInstaller, no Python needed): bubnbros-server,
                   "bubnbros-server --web" for the web launcher, which
                   only offers the native client (built with
                   build_server.py --native-client-only); the Linux
                   packages add the native client
  play-alone       the native client with that server built in: one
                   program, to join games or play alone

GitHub releases have bubbros-native-VERSION (.tar.gz / .zip), and
bubbros-server-embedded-TARGET and bubbros-play-alone-TARGET for Linux,
Windows and macOS.  The Linux packages bubbros-native,
bubbros-server-embedded and bubbros-play-alone conflict with each other;
they all add the menu entry "Bub-n-Bros play alone", and the first two
also "Bub-n-Bros server" (the web launcher).  Packaging files:

  Arch Linux:        packing/arch/PKGBUILD.txt (copy to PKGBUILD, makepkg;
                     builds the three packages)
  Debian, Ubuntu:    debian/   (from bub-n-bros/: dpkg-buildpackage -us -uc -b)
  Fedora, Mageia,
  OpenMandriva:      packing/rpm/bubbros.spec   (rpmbuild -ba, once per
                     package: --define "variant server-embedded" or
                     "variant play-alone"; native is the default)

All of them use packing/linux/build.sh and packing/linux/install.sh.
They need Rust 1.75 or newer, and network access while building: cargo
downloads the native client's dependencies (run "cargo vendor" in
rust-client/ first for builders without network access), and pip
installs PyInstaller (or set PYINSTALLER_PYTHON to a Python that has
it).  The GitHub workflow .github/workflows/linux-packages.yml builds
and tests the packages for Ubuntu 24.04, Debian 13, Fedora and
OpenMandriva.
